# CapchunScreen v0.1.0 実装計画・報告

対応: [要求](v0.1.0-req.md) / 作成: 2026-10-15 / 状態: 実装中

## 0. 事前確認

- 移植先は存在せず、親はfeature/full-refactoringで変更なし。子はmainで新設する。
- 元Pythonは音声なし。TSVヘッダーはtimestamp、frame、x、y、click、keys。映像への入力演出焼き込みはない。
- 旧WGC処理は仮定APIと例外無視によるPrintWindowへの切替を含む。C#では正式なHWND interopを使用し、専用窓取得失敗時にデスクトップ取得へ切り替えない。
- 旧画質選択は録画へ渡らない。C#ではFFmpegのCRFへ反映する。
- 旧TSVは全量メモリー保持後に別スレッド保存。C#では逐次書込みと完了待機にする。
- 実行環境: .NET SDK 10.0.402、WindowsDesktop 10.0.13。FFmpegは既存ローカル実行ファイルを検証に利用する。

## 2. 実装方針

- R1: Python依存なし。net10.0-windows10.0.19041.0、x64、PerMonitorV2。設定はLocalApplicationData/CapchunScreenに保存する。旧設定は自動変更しない。
- R2: CaptureTarget/IFrameSourceを境界とし、GDIの画面取得とWGCの専用窓取得を分離する。窓消失・最小化は理由を表示する。
- R3: BGRフレームをFFmpegへ渡し、H.264で保存。単調時計、固定出力サイズ、停止時のエンコーダ終了確認を行う。出力は一時名で作り、完了後に公開名へ移す。FFmpeg場所は設定可能。
- R4: 録画中だけ入力フックを有効にし、短い押下を蓄積する。単独文字の記録は明示選択にする。動画時刻と同じ基準でTSVを逐次保存する。
- R5: 録画一覧と外部の既定プレイヤーで再生を提供する。改名は動画とTSVをまとめて扱い、衝突を防ぐ。削除は確認後ごみ箱へ送る。
- R6: 合成入力・合成映像を基本検証に用いる。実画面は検証専用窓で確認し、ユーザーの既存録画・設定を変更しない。

## 3. 影響範囲

新しいtools/CapchunScreen内と、親の独立Gitリンク・紹介だけ。元Python、他ツール、本体の配布/カタログを変更しない。

## 4. 実装で判明した追加対応

- 実機の静止窓ではWGCフレームプールのRecreateだけだとサイズ変更後のフレームが供給されない。実測で初回480×300から560×340への変更時に再現。同一GraphicsCaptureItemのプールとセッション双方を再作成し、初期フレームを取得する方式へ修正した。
- 取得が遅い場合は直前映像で時間を補い、5秒超の遅れを明示的な性能エラーにする。窓リサイズ時の黒余白・拡縮をTSVの座標にも適用する。
- 録画キーCtrl+Shift+F9を途中で修飾キーだけ離した場合の履歴混入を、F9解放までの抑制状態で防いだ。
- 入力記録ONなのに入力源がない呼出しは、開始前に拒否する。

## 6. 検証結果

P0: .NET 10/Windows SDK依存復元とDebugビルド成功（警告0、エラー0）。制限環境ではNuGet監査取得NU1900が発生したため、許可された接続でrestore後に再ビルドした。

P1: `logs/tests-20261015-005837/`で合成入力・MP4/MKVの実エンコード/デコード54件成功。日本語パス、FPS、ffprobe実フレーム数、TSV行数、遅い取得、停止、失敗非公開、設定拒否を含む。F9解放順追加後の入力等41件も成功し、同フォルダーinput-regression.logへ保存した。

実WGC: `logs/capture-resize-regression-20261015/`で専用の合成窓を使用。480×300→560×340→360×220→620×380、他窓分離/GDI対照、位置追従、最小化・対象終了・cancel・Dispose後拒否が成功。親も緑の対象だけのWGC画像と、紫の覆い窓が入るGDI対照画像を確認した。制限環境のAccessDeniedと、修正前resize失敗も別runへ保存。実際の利用アプリ全般の互換性はこの試験だけでは保証しない。

P2: 録画画面、設定、録画一覧、ペア改名・ごみ箱、単一起動、ホットキーを実装。設定の破損原本保護と再保存、改名の衝突・途中失敗の巻戻し、大小文字だけの改名を検査した。900×720/740×620の両タブ・ダイアログ配置と、終了待機中の録画再開始防止を確認。「対象を更新」の4pxはみ出しを修正。非表示UI検査の子ハンドル生成とSynchronizationContext復帰も直した。実エンコードを含む統合検査は`logs/p2-verified-20261015/test.log`で141件成功（先行した独立プレビュー15件を含む）。

ユーザーの追加回答により、仮想カメラ・独立プレビュー・複数動画同時再生をP3へ追加した。仮想カメラは既存UnityCaptureの送信プロトコルを移し、ドライバー自動導入はしない。現PCでの登録なしと、合成受信先によるプロトコル検証を分けて扱う。

P3: 独立プレビュー、UnityCapture共有メモリ送信、最大16本の動画同時再生を実装。レビューで個別一時停止の逆動作、キーボードシークの値消失、スライダー自動寸法による操作領域はみ出し、仮想カメラ停止と画面終了の競合、終了時の設定保存失敗後の操作復旧を修正した。

- `logs/playback-final-20261015-013659/test.log`: ビルド警告0/エラー0、統合162件成功。16枠19ボタンの実寸、全体から個別操作への状態遷移、赤/青が時間で変化する動画の前後シーク、16個の実FFmpegデコーダー同時取得・全終了を含む。
- `logs/virtual-camera-relay-20261015/tests.log`: 合成受信プロトコルと配信ワーカー25件成功。色順・上下・header・event・容量・timeout・cancel・No Signal・停止Task共有・Bitmap解放を検証。
